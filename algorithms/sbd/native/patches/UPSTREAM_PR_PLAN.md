## The fix (what the PR changes)

`TwoDiffCorrelation` split its scatter on `si == sa` / `si == sb` using the sorted-index pairing
`(I=min(i,j) -> A=min(a,b)), (J -> B)` with two parities on the unchanged bra determinant. That is
correct for **same-spin** double excitations but wrong for **opposite-spin** ones: it pairs
creation/annihilation operators across spins and ignores the intermediate determinant, giving a
wrong Fermi sign on some ab/ba 2-RDM elements.

The PR branches on `si != sj`:

- **Opposite-spin (ab/ba)** — recompute the sign with spin-consistent pairing
  (alpha-creation<->alpha-annihilation, beta-creation<->beta-annihilation) and the intermediate
  determinant, expressed purely on the bra det, then scatter into blocks 2 (ab) and 1 (ba):

  ```c++
  int aCr = (i % 2 == 0) ? i : j;   // alpha creation
  int bCr = (i % 2 == 0) ? j : i;   // beta  creation
  int aAn = (a % 2 == 0) ? a : b;   // alpha annihilation
  int bAn = (a % 2 == 0) ? b : a;   // beta  annihilation
  int p1 = min(aCr,aAn), q1 = max(aCr,aAn);
  int p2 = min(bCr,bAn), q2 = max(bCr,bAn);
  double s = 1.0;
  parity(det, p1, q1, s);
  if (p1 < bCr && bCr < q1) s *= -1.0;
  if (p1 < bAn && bAn < q1) s *= -1.0;
  parity(det, p2, q2, s);
  // scatter s * conj(WI) * WJ into twobody[2] (ab) and twobody[1] (ba)
  ```

- **Same-spin (aa/bb)** — unchanged; the original `si==sa` / `si==sb` scatter is moved verbatim into
  the `else` branch.

The full diff for both files is `patches/sbd-rdm-opposite-spin-sign.patch` (GPU) and
`patches/sbd_mpi-rdm-opposite-spin-sign.patch` (MPI).

## Evidence to attach to the PR

- **CPU/PySCF numerical proof**: `patches/test_rdm_vs_pyscf.py` + `patches/RDM_PYSCF_PROOF.md`.
  Patched matches PySCF `make_rdm12s` to ~1e-16 for the 1-RDM and all four 2-RDM blocks and
  reconstructs the Davidson energy; original gets only the opposite-spin block wrong (max|Δ| ~1e-2,
  `E_recon` off by ~1–9 mHa). 2/2 cases pass (`H3_asym_doublet`, `OH_doublet`).
- **GPU binary verification**: job062419, NORB=20, `diag-gpu_uhf_diag`,
  `Delta(E_recon - E_davidson): +0.937 mHa -> -6.25e-13 Ha` (jobs 164204 -> 164217, 2026-09-26).

## Turning the proof into an upstream test artifact

The upstream repo auto-discovers C++ tests via `tests/functionality/Makefile` (see the docstring of
`algorithms/sbd/tests/test_rdm_carryover.py`). The natural upstream artifact is a small
`tests/functionality/test_gpu_rdm_correlation.cc` that builds the four 2-RDM blocks for a fixed tiny
CI vector and checks the opposite-spin elements against **golden values generated by**
`test_rdm_vs_pyscf.py`. Plan:

1. Pick one tiny fixed case (e.g. `H3_asym_doublet`, norb=3, 9 dets) and dump its CI vector +
   expected ab/ba block from the Python replica (add a `--dump-golden` path if convenient).
2. Write `test_gpu_rdm_correlation.cc` that feeds that CI vector through `TwoDiffCorrelation` and
   asserts the ab/ba elements match the golden values, plus `E_recon == E_davidson`.
3. Keep the Python replica in qcsc-prefect as the golden-value generator / regression oracle.

If the maintainers prefer, the Python replica can instead be contributed under `tests/` as-is
(it only needs numpy + pyscf), avoiding a bespoke C++ harness.

## PR text (draft)

**Title**: `Fix opposite-spin 2-RDM double-excitation sign in TwoDiffCorrelation`

**Body**:
> `TwoDiffCorrelation` builds the spin-resolved 2-RDM by scattering with a sign computed from a
> sorted-index pairing `(min(i,j)->min(a,b)),(max->max)` and two parities on the bra determinant.
> This is correct for same-spin double excitations (aa/bb) but wrong for opposite-spin ones
> (ab/ba): the pairing crosses spins and ignores the intermediate determinant, so some ab/ba
> elements get the wrong Fermi sign.
>
> This branches on `si != sj` and, for the opposite-spin case, recomputes the sign with
> spin-consistent pairing and the intermediate determinant (expressed on the bra det), scattering
> into the ab and ba blocks. Same-spin scatter is unchanged.
>
> Symptom fixed: `E_recon != E_davidson` when reconstructing the energy from the RDMs (the 2-RDM is
> otherwise silently wrong on the opposite-spin block). Verified element-wise against PySCF
> `make_rdm12s` (1-RDM + all four 2-RDM blocks match to ~1e-16 after the fix; the opposite-spin
> block was off by ~1e-2 before) and on the GPU binary (NORB=20: `E_recon-E_davidson` +0.937 mHa ->
> -6.25e-13 Ha).
>
> Both `correlation_thrust.h` (GPU/tpb path) and `correlation.h` (host path) are updated so they
> stay consistent.
